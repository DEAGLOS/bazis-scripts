# Справочник по скриптам Базис-Мебельщик (наработки из практики)

Собрано в ходе разработки инструмента "объёмный текст из шрифтов" и правки
скрипта шкафа-пенала. Кидай этот файл в начале нового чата про скрипты
Базиса — избавит от повторного нащупывания API вслепую.

## Общая архитектура
- Скриптовый движок Базиса — урезанный JS (без DOM, без `fetch`), но с
  обычными JS-конструкциями: функции, массивы, `JSON.parse`/`JSON.stringify`.
- **Файлы скриптов сохраняй в кодировке CP1251** (Windows-1251), не UTF-8 —
  иначе русский текст в диалогах превращается в кракозябры. Обычный
  `.js`-файл с кириллицей внутри обязательно конвертировать через
  `iconv -f UTF-8 -t CP1251`.
- Официальный справочник API есть в самом Базисе как файл `types.js`
  (описание всех объектов/методов с сигнатурами и подсказками на русском) —
  если он есть под рукой, это самый надёжный источник истины, точнее любых
  примеров/документации.

## Оси и системы координат
- **X = ширина, Y = высота, Z = глубина.**
- `AddHorizPanel(x1, z1, x2, z2, y)` — горизонтальная панель (полка/дно):
  спан по ширине и глубине, позиция по высоте.
- `AddVertPanel(z1, y1, z2, y2, x)` — вертикальная панель (боковина): спан
  по глубине и высоте, позиция по ширине.
- `AddFrontPanel(x1, y1, x2, y2, z)` — фасадная панель: спан по ширине и
  высоте, позиция по глубине.
- Во всех трёх — начальная координата = "ближняя" грань, панель растёт по
  толщине материала в сторону положительных значений соответствующей оси.
- `AddExtrusion(name)` — объект выдавливания профиля. **`Orient(axisZ, axisY)`**:
  первый параметр — куда пойдёт направление выдавливания (толщина), второй —
  куда "верх" контура. Для объёмных букв (контур лежит в плоскости
  ширина-высота, толщина — в глубину): `Ext.Orient(AxisZ, AxisY)`.
  **Не** `Orient(AxisX, AxisY)` — это для профилей/реек, вытянутых вдоль X.
- Есть также `Axis_X`, `Axis_Y`, `Axis_Z` — противоположные направления.

## Contour2D — работа с контуром (панели, вырезы, выдавливание)
Один и тот же тип объекта используется у `Panel.Contour`, `NewContour()` и
`Extrusion.Contour`.
- `NewContour()` — создать отдельный контур.
- `Contour.AddLine(x1,y1,x2,y2)` — отрезок. Работает и на панелях, и на
  выдавливании — контур можно рисовать произвольной ломаной, не только
  готовыми фигурами.
- `Contour.AddArc3(p1, p2, p3)` — дуга через 3 точки (начало, точка НА дуге,
  конец). `p1`/`p2`/`p3` — через `NewPoint(x,y)`.
- `Contour.AddArc(p1, p2, centre, bool)` — дуга по началу/концу/центру
  (может быть удобнее AddArc3 для расчётных случаев, где центр уже известен).
- `Contour.AddCircle(x,y,r)`, `AddRectangle(x1,y1,x2,y2)`,
  `AddRoundRect(x1,y1,x2,y2,r)` — готовые примитивы.
- `Contour.Rounding(x,y,radius)` — скругление угла в этой точке одним
  вызовом. **Осторожно**: вызов `Rounding` в цикле по многим точкам подряд
  вёл себя разрушительно (путал вершины, съедал контур) — так и не
  разобрались до конца, почему. Если нужно массовое скругление многих
  углов — считать координаты фаски самому в питоне и сразу вписывать как
  `AddLine`/`AddArc3`, не полагаться на `Rounding` в цикле.
- `Contour.Facet(x,y,size)` — фаска (срез угла).
- `Contour.Subtraction(otherContour)` — вычесть контур (дырка).
  **Обязательный порядок**: сначала ВСЕ `Addition`, потом ВСЕ `Subtraction`
  — если вычитать раньше, чем всё добавлено, дырка пропадает/не из чего
  вычитать.
- `Contour.Addition(otherContour)` — добавить (объединить) контур.
- `Contour.Fit(x1,y1,x2,y2)` — вписать/масштабировать контур в прямоугольник.
- `Contour.Symmetry(x1,y1,x2,y2,bool)` — зеркало относительно произвольной
  линии (не только через `AxisX`/`AxisY`).
- `Contour.Load(file.frw)` — загрузить готовый профиль (например, профиль
  фрезы) из файла.
- `Contour.Clear()` — очистить контур перед перерисовкой с нуля.

## КРИТИЧЕСКИ ВАЖНО: StartEditing + Build
Самый дорогой урок за весь разговор. Симптом: скрипт "успешно" отрабатывает
(без JS-исключений), но объект либо не строится, либо строится с дырами/
пропавшими частями, и никакой alert/try-catch этого не ловит.
- Перед правкой контура уже существующего объекта — `StartEditing(Obj)`.
- **`AddExtrusion` тоже требует `StartEditing(Ext)` сразу после создания**,
  прежде чем вызывать `Ext.Contour.Addition/Subtraction`. Без этого — тихий
  сбой без внятной ошибки.
- **После всех правок контура — обязательно `Obj.Build()`** (или
  `Ext.Build()`). Без явного `Build()` в конце геометрия может быть не
  зафиксирована.
- Для панелей, которые были только что созданы через `AddHorizPanel` и
  т.п. (не через `AddExtrusion`), `StartEditing` обычно не требуется для
  первой правки контура — но `Build()` после `Contour.Subtraction` всё
  равно нужен.

## Пазы и фрезеровка (Cut)
```javascript
Cut = Panel.AddCut('Название');   // или Panel.Cuts.Add() - оба варианта видел
Cut.Trajectory.AddLine(x1,y1,x2,y2);      // путь паза по лицу панели
Cut.Contour.AddRectangle(x1,y1,x2,y2);    // сечение паза (глубина/ширина)
Cut.Contour.Load('Фреза.frw');            // или загрузить готовый профиль фрезы
Cut.Contour.Symmetry(0,0,1,0,false);      // зеркалить профиль
Cut.Contour.Move(0, Panel.Thickness);     // сдвинуть на другую грань
```
Чтобы паз шёл от заднего лица, а не переднего — в `Contour.AddRectangle`
использовать координаты относительно `Panel.Thickness`, а не от нуля
(`(0, Panel.Thickness, 10, Panel.Thickness-5)` вместо `(0,0,10,5)`).
Наш паз под заднюю стенку шкафа так и не довели до конца — если вернётесь
к этому, начинайте с этого чистого примера, а не с мутного из
"Тумбочки", там были посторонние допуски (+0.5 и т.п.).

## Диалог свойств (Action.Properties)
```javascript
Prop = Action.Properties;
X = Prop.NewNumber('Название', default);
S = Prop.NewString('Название'); S.Value = 'текст';
C = Prop.NewCombo('Название', 'Пункт1\nПункт2\nПункт3'); C.ItemIndex = 0;
G = Prop.NewGroup('Название группы');       // сворачиваемая секция
M = Prop.NewMaterial('Название');            // выбор материала из библиотеки
Butt = M.NewButt('Кромка');                  // выбор кромки (внутри материала)
F = Prop.NewFurniture('Название');           // выбор фурнитуры
Sel = Prop.NewSelector('Название');          // кнопка выбора файла
Sel.OnClick = function(){ Sel.Value = system.askFileName('frw'); };
B = Prop.NewBool('Название', true);          // чекбокс
B.OnChange = function(){ B.ChildrenEnabled = B.Value; }; // вкл/выкл вложенные поля
Img = Prop.NewImage('Название', 'файл.wmf'); Img.MaxHeight = 250;
OkBtn = Prop.NewButton('Построить');
Prop.OnChange = function(){ DeleteNewObjects(); Make(); };   // живой предпросмотр
OkBtn.OnClick = function(){ DeleteNewObjects(); Make(); Action.Commit(); Action.Finish(); };
```
- **`Action.Finish()` обязателен после `Commit()`** в обработчике кнопки —
  иначе повторное нажатие построит ещё одну копию поверх старой (действие
  остаётся "живым" из-за `Action.Continue()`).
- `Action.Continue()` в конце скрипта — держит диалог/действие открытым,
  без него всё исполняется один раз и закрывается.
- `DeleteNewObjects()` — стирает объекты, созданные в текущем запуске (для
  живого предпросмотра при изменении параметров).

## Файлы, чтение/запись, модульность
- `system.require('файл.js')` — подключает и ВЫПОЛНЯЕТ другой скрипт (для
  библиотек функций, не для чистых данных).
- `system.readTextFile('файл.txt')` + `JSON.parse(...)` — способ читать
  ЧИСТЫЕ ДАННЫЕ без выполнения кода. Полезно, чтобы шрифты/датасеты не
  светились в списке скриптов Базиса как исполняемые файлы — используем
  `.txt`, не `.js`, для файлов-данных.
- `system.fileExists('файл')`, `system.writeTextFile(...)`,
  `system.askFileName('расширение')`, `system.askWriteTextFile(...)`.
- **JSON-ловушка**: если формируешь `.txt`/`.json` файлы данных сам (питоном
  или иначе), проверь, что числа НЕ сериализуются в научной нотации
  (`2.76e-05`) — похоже, `JSON.parse` в Базисе с такими числами не
  справляется и роняет всю загрузку целиком (не одну букву/деталь, а
  вообще всё). Если готовишь JSON в Python — не используй `json.dumps`
  для float в лоб, форматируй вручную с фиксированной точкой
  (`f'{x:.7f}'.rstrip('0').rstrip('.')`).
- Манифест-файл (обычный `.txt` со списком имён, по одному на строку) —
  удобный способ добавлять новые файлы данных (шрифты, схемы, что угодно),
  не трогая основной скрипт: скрипт читает манифест и подгружает всё, что
  там перечислено, без хардкода имён внутри кода.

## ParametricBlock — редактируемые объекты
```javascript
if (!ParametricBlock) {
    // первое построение
} else {
    // редактирование уже существующего объекта - можно подтянуть текущие
    // размеры: OldPanel = ParametricBlock.Find('Имя панели');
    // Dl.Value = OldPanel.Contour.Width;
}
CurBlock = BeginParametricBlock("Имя");
    ...строим панели...
EndParametricBlock();
```
Даёт возможность выделить готовый объект и перезапустить скрипт для правки
параметров, а не только для построения с нуля. Не использовали в финальных
инструментах, но пригодится для мебели, которую планируется потом
редактировать через UI Базиса.

## Крепёж и фурнитура
```javascript
Furn = OpenFurniture('Путь\\Файл.f3d');
Furn.Mount(Panel1, Panel2, x, y, z);      // крепёж между двумя панелями
Furn.Mount1(Panel, x, y, z, angle);        // крепёж на одной панели (ручка и т.п.)
```
Стандартная сетка присадки (32мм) считается так:
```javascript
Ost = (Length - Offset) % 32;
K = (Length - Offset - Ost) / 32;
Step = (Length - K*32) * 0.5;   // центрирующий отступ
```

## Шрифты и объёмный текст — отдельный большой блок
Bazis не умеет парсить TTF/OTF — вся работа со шрифтами (fontTools,
Python) идёт СНАРУЖИ, результат "запекается" в данные (JSON: линии+дуги
в относительных em-единицах), которые скрипт грузит через
`readTextFile+JSON.parse`.
- TrueType-кривые квадратичные — раскладываются на `AddLine`/`AddArc3`.
- Для гладких дуг (не гранёный многоугольник) — техника "биарк": делить
  исходную кривую на 2 дуги с точкой стыка, подобранной так, чтобы
  касательные совпадали ТОЧНО (численный подбор через бисекцию, не через
  приближение серединой кривой — иначе на стыках дуг видны "заломы"/
  "ямки", особенно на выпукло-вогнутых переходах типа талии буквы S).
- **Опечатки/шипы дизайна шрифта** ("чернильные ловушки", ink traps) —
  реальные, намеренные микро-детали в шрифтах (особенно засечковых типа
  Times New Roman), invisible при обычном кегле, но превращающиеся в явные
  уродливые крюки при выдавливании буквы на сотни мм. Чинится точечно:
  найти координаты (или продлить соседние прямые до истинного пересечения,
  если нужен острый угол вместо крюка) и вырезать/заменить конкретные
  команды по индексу.
- Составные (`composite`) глифы (например, кириллица "О" ссылается на
  латинскую "O" как компонент) — нужно разворачивать через
  `fontTools.pens.recordingPen.DecomposingRecordingPen`, обычный
  `RecordingPen` их не разворачивает.
- "Гнутая панель" в Базисе требует АБСОЛЮТНОЙ гладкости (сопряжения) по
  всему контуру без единого излома — экспериментировали со скруглением
  всех углов, получилось очень хрупко (баги на стыках дуг с линиями,
  накопление погрешности на крошечных радиусах). Если снова понадобится —
  закладывать на это отдельную сессию, не мешать с остальной работой.

## Общий процесс отладки без доступа к живому Базису
- У Claude нет живого Базиса для тестов — весь код проверяется только
  математически/численно (самопересечения, разрывы контура, углы между
  касательными) до того, как пользователь реально прогонит в программе.
- Самый эффективный способ отладки визуальных дефектов — **скриншот с
  разметкой**: что было (серым/линиями), что должно быть (стрелками/другим
  цветом). Текстовое описание "тут кривовато" почти бесполезно для точной
  локализации бага.
- Если Base is не даёт вменяемого текста ошибки — можно обернуть
  подозрительные вызовы в `try {...} catch(e) { alert(e.message); }`,
  чтобы вытащить точный текст ошибки движка, а не гадать вслепую.

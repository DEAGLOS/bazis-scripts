# Веб-просмотрщик 3D-моделей Базиса (bazis_json_viewer_v2)

Читается автоматически при запуске Claude Code в этой папке. Общая
архитектура и инструменты — здесь, детали по темам — в `docs/`.

## Что это
Отдельный проект от генерации мебельных скриптов (тот — в соседней папке
`bazis-project`, если она есть рядом). Здесь — браузерный 3D-просмотрщик
(HTML+Three.js) моделей, экспортированных из Базис-Мебельщика.

**Важно: писать "Базис"/"Bazis", НЕ "Base is"** — регулярно путается,
правило зафиксировано твёрдо.

## Архитектура — гибрид JSON + .dae
Прямое чтение бинарного `.b3d` отклонено (объектный граф не декодирован,
см. `docs/b3d-format.md` — разведка, не парсер). Вместо этого:
- **JSON** (`Экспорт_JSON_3D.js` — свой скрипт, запускается внутри
  Базиса, `system.askWriteTextFile`, обход `Model`→`ProcessObject` по
  `List`) — источник ВСЕХ панелей (как боксы) и фурнитуры без 3D-формы
  (проволочный контур). Полный список полей — см. ниже.
- **.dae** (штатный экспорт Базиса, ТОЛЬКО руками через меню — из
  скрипта не вызывается, скриптового экспорта в OBJ/glTF нет) —
  источник настоящей 3D-формы и материала там, где физически есть.
- Общий ноль координат у JSON и .dae подтверждён численно. Разворот осей
  Z_UP→Y_UP берёт на себя `THREE.ColladaLoader` сам.
- Кодировка выходного файла экспортёра часто CP1251 — автооткат
  UTF-8→CP1251 и в python-скриптах, и во вьювере.

## Актуальный набор файлов
- `bazis_json_viewer_v2.html` — единственная актуальная версия вьювера
  (более ранняя `bazis_json_viewer.html` и `json_to_gltf.py` — устарели,
  не поддерживаются).
- `material_config.js` — правит пользователь в блокноте, лежит РЯДОМ с
  вьювером (см. `docs/materials.md`).
- `Экспорт_JSON_3D.js` — скрипт для Базиса (использует общие правила
  кодировки/API из проекта генерации скриптов, если он рядом).
- `Диагностика_Фурнитура_2D_3D.js` — вспомогательный.

## Поля JSON-экспортёра
Все поля читаются в `try/catch` — Базис бросает исключение на
несуществующем свойстве, не возвращает `undefined` тихо.

| Поле | Источник | Примечание |
|---|---|---|
| `Name`, `ArtPos` | как есть | |
| `Group` | верхнеуровневый блок или `null` | вьювер пока не использует |
| `Size` | `GSize.x/y/z` | ЛОКАЛЬНЫЙ габарит, X=ширина/Y=высота/Z=глубина |
| `Corners` | 8 угловых точек, МИРОВЫЕ координаты | фикс. порядок битов x,y,z: 0=min,min,min…7=max,max,max |
| `Color` | `Material.DiffuseColor`, BGR | `null` у фурнитуры (эвристика "это фурнитура") |
| `LineColor` | `Obj.Color` | цвет ОБВОДКИ объекта, не материала |
| `MaterialName` | `Material.MaterialName` | НЕ `.Name` |
| `TexturePath` | `Material.PathAbsolute()` | |
| `TextureOrientation` | 0=None/1=Horizontal/2=Vertical | относительно ЛОКАЛЬНЫХ осей, см. `docs/geometry.md` |
| `Value` | только `Size3D`/размерные линии | число выноски |
| `Butts` | `Obj.Butts` → `{ElemIndex,Material}` | мэппинг на грани не до конца установлен, см. `docs/materials.md` |
| `Contour` | `null` если `IsContourRectangle()`, иначе сегменты | реальный контур панели, см. `docs/materials.md` (buildContourPanelMesh) |
| `Cuts` | `Obj.Cuts` → `{Name,Sign,TrajMin,TrajMax,ProfileWidth,ProfileHeight}` | экспортёр готов, во вьювере декаль ещё не размещена |

`Pos1`/`Pos2`/`TopPos` — ПОДТВЕРЖДЕНО НЕ читаются у `Size3D` (это
параметры метода `MakeOnPoints`, не свойства объекта).

## Группировка блоков + выборочный экспорт
`HasSelection(Obj)` — рекурсивная проверка `.Selected` (try/catch),
проверяется на САМОМ объекте (и `List`, и лист) ПЕРЕД рекурсией внутрь.
Фильтрация выделения (`if (AnySelected && !HasSelection(Child)) continue;`)
стоит НА КАЖДОМ уровне вложенности рекурсии `ProcessObject`, не только в
верхнем цикле `DoExport` — иначе ломается на проектах с одним общим
блоком-обёрткой на весь проект вместо отдельных блоков-шкафов рядом.

Уточнение (`ForceInclude`/`PassDown` в `ProcessObject`): если блок
выделен ЦЕЛИКОМ САМ (`Obj.Selected`), дальше внутри него фильтрация
ПО ДЕТЯМ уже не применяется — листовые детали внутри выделенного блока
обычно не помечены `.Selected` каждая по отдельности, только сам блок,
и безусловная фильтрация на каждом уровне это раньше срезала (экспорт
целиком выделенного блока давал пустой/урезанный результат). Флаг
прокидывается рекурсивно вниз (`PassDown = ForceInclude || SelfSelected`).

После экспорта — `alert(...)` с напоминанием сделать `.dae` отдельно
вручную.

`Action.Properties.Save/Load` (persistence диалога материалов в
legacy-ветке для старых версий Базиса, например 2022) — оборачивать в
`try/catch`, не полагаться на тихий no-op на несуществующем файле:
непойманное исключение здесь до 2026-08-14 роняло скрипт ДО появления
кнопок диалога — выглядело как «скрипт не экспортирует» именно на этих
версиях.

## Фильтры вьювера
`IGNORE_NAMES={"габаритная рамка"}` (служебный бокс всего проекта).
Вырожденные объекты (`min(Size)<0.5мм`) пропускаются, КРОМЕ объектов с
`Value` (размерные линии физически тонкие). Фурнитура определяется как
`Color===null` (эвристика; надёжнее было бы `Obj.Holes.Count>0`
duck-typing, не переписано).

## Детали по темам
- `docs/geometry.md` — геометрия панелей, BOX_FACES, локальные оси vs
  мировые векторы (ключевой урок всего проекта), UV, направление
  текстуры, поворот кромки, зеркалирование.
- `docs/materials.md` — материалы/текстуры, диалог классификации,
  Plastics-облицовка, реальный контур пласти, разрез (Sims + плоскость).
- `docs/fasteners.md` — фурнитура, матчинг JSON↔.dae, "штамп по шаблону".
- `docs/ui.md` — тулбар, зеркало (Reflector), env-карта, размерные
  линии, офлайн-версия, найденные UI-баги.
- `docs/b3d-format.md` — разведка бинарного формата .b3d (не парсер,
  отложено пользователем).

## Отладка
Нет живого Базиса для скрипта-экспортёра и нет полноценного браузера для
вьювера — код проверяется математически/логически до реального теста
пользователем. `try/catch` + `alert(e.message)` в скрипте экспортёра —
вытаскивает точную ошибку вместо тихого сбоя.

## Правило: не пересобирать без запроса
Известные незакрытые баги/недоделки (см. "ОТКРЫТЫЕ ЗАДАЧИ" в
`docs/materials.md`) — не чинить проактивно, ждать явной просьбы
пользователя.

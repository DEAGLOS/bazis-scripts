# Формат .b3d (разведка, не парсер)

Читать вместе с `../CLAUDE.md`. Отложено пользователем — не продолжать
проактивно, ждать явной просьбы вернуться к теме.

## Зачем смотрели
Идея — читать нативный проектный файл Базиса напрямую вместо JSON+.dae.
Потенциально самый точный источник данных (материалы, толщины, позиции,
крепёж) — но объектный граф не декодирован, разбор отложен как слишком
рискованный без документации формата (ошибки будут тихими, без сигнала
"не строится", как в самом Базисе при неверном JS).

## Структура файла (подтверждено разбором реального файла)
1. Сигнатура `BZ85` в начале.
2. Небольшой заголовок, поля-строки (длина-префикс int32 LE + строка):
   `ID`, `Name`, `Header`, `Params`, `Article`, `Version`, `FileType`,
   `ExtraInfo`, `Furniture`, `LDistance`, `Thumbnail`, `RotationList`,
   `LDistance.Max`, `LDistance.Min`.
3. Встроенное PNG-превью проекта (по сигнатурам `IHDR`/`IDAT`/`IEND`) —
   картинка для списка файлов в интерфейсе Базиса.
4. Сразу после PNG (`IEND`+8 байт) — короткая строка в UTF-16LE с
   названием проекта.
5. Дальше — один большой zlib-поток (сигнатура байт `78 9C`) на весь
   остаток файла. Разжимается штатным `zlib.decompress()` в Python.

## Внутри распакованного блока
Таблица интернированных строк в начале (свойства ссылаются на индекс, не
хранят имя каждый раз):
- Первые 4 байта (int32 LE) = количество строк.
- Дальше подряд: (int32 LE длина, байты строки) на каждую, начиная с
  индекса 0 (пустая строка).
- Строки примерно по возрастанию длины: однобуквенные (`T`,`X`,`Y`,`Z`),
  двухбуквенные (`ID`,`Mt`,`Rw`,`Rx`,`Ry`,`Rz`), дальше длинные составные
  (`InterlayerThickness`, `DateTimeLastSaved`, `FirstOperationNumber`).
- После таблицы (в тесте — offset 20252 из 2521669) идёт объектный граф
  (объекты/панели/крепёж/анимации), ссылающийся на индексы таблицы.
  **Эта часть НЕ разобрана** — как объекты нанизаны, как закодированы
  числа/вложенность — отдельный, более рискованный этап.

## Найденные имена полей (из таблицы 1435 строк)
Материал: `Name`, `Color`, `Thick`, `Width`, `Height`, `MtWidth`,
`UseColor` (вероятный переключатель "Текстура/Цвет" — не найден в JS
API, см. проект генерации скриптов `docs/materials.md`), `StartName`,
`Thickness`. Другие: `Cut`, `Butt`, `Anim`, `Bent`, `Clip`,
`JointLength`, `RotHoleIndex`/`RotTriIndex`/`RotEdgeIndex`,
`Symmetrized`, `Transparency`, `AmbientLight`, `MapRoughness`,
`MapGlossiness`, `MapFrenselIOR`, `MapSelfIllumination`, `VersionMajor`,
`VersionMinor`, `DateTimeLastSaved`, `ObjectNotes`, `PerspAspect`,
`NavAngleOfView`, `FirstOperationNumber`.

## Если возвращаться к теме
Рабочий метод: взять два `.b3d` файла с РОВНО одним известным отличием
(например поменять в Базисе толщину одной полки и пересохранить),
сравнить побайтово — изменившееся с высокой вероятностью и есть
закодированное значение в контексте объекта. Постепенно, диффами, можно
нащупать структуру объектного графа.

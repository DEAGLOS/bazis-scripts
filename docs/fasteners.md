# Фурнитура — матчинг JSON ↔ .dae

Читать вместе с `../CLAUDE.md` и `geometry.md` (те же структурные приёмы
— локальные оси, не мировые векторы).

## Базовый матчинг (подтверждено рабочим)
`THREE.ColladaLoader` (r128, ТОЛЬКО jsdelivr — на cdnjs нет
`examples/js`-аддонов для r128). Для объектов JSON с `Color===null`
(эвристика "это фурнитура") ищем в `.dae` узлы с той же нормализованной
строкой имени (`\r`→пробел, схлопнуть пробелы, lowercase — XML-парсер
нормализует `\r` в атрибутах, сырое `Obj.Name` в JSON — нет).
Масштаб `.dae`: числа физически в мм при заявленном `unit meter="1"` —
`daeRoot.scale.multiplyScalar(0.001)`.

## "Штамп по шаблону" — архитектура
Старая схема (искать ближайший по позиции узел `.dae` для КАЖДОГО
экземпляра фурнитуры) рискует зацепить чужую деталь у соседних шкафов с
одноимённой фурнитурой (например при выборочном экспорте одного шкафа
из нескольких похожих). Текущая схема — форма извлекается из `.dae`
ОДИН РАЗ на уникальное ИМЯ, дальше расставляется только по данным JSON:

```
frameMatrixFromCorners(pts)       — Matrix4 локального фрейма из 8 угловых
                                     точек JSON-элемента (тот же приём, что
                                     у панелей)
extractLocalTemplate(daeObject, sourceFrameMatrix)
                                   — переводит вершины найденного .dae-узла
                                     в локальный фрейм ОДНОГО JSON-элемента
                                     (источник шаблона), обходя все Mesh в
                                     поддереве узла
instantiateTemplate(parts, targetFrameMatrix)
                                   — штампует локальный шаблон в мир через
                                     фрейм ЛЮБОГО ДРУГОГО JSON-элемента с
                                     тем же именем — к чужому .dae-узлу
                                     больше не обращаемся
```

Нормали пересчитываются заново (`geo.computeVertexNormals()`) после
трансформации КАЖДОГО инстанса — надёжнее, чем тащить через матрицу
(зеркальные экземпляры меняют ориентацию граней, нормали бы съехали).

## Ловушка при построении шаблона — позиционная проверка обязательна
`extractLocalTemplate` ПРЕДПОЛАГАЕТ, что фрейм ТЕКУЩЕГО (первого по
счёту в цикле) JSON-элемента описывает позицию именно того `.dae`-узла,
который вернул поиск по имени. Без проверки позиции это даёт
произвольное, но систематическое рассогласование (шаблон строится один
раз — сдвиг одинаковый у ВСЕХ копий этого имени).

**Обязательное правило**: позиционное сравнение
(`MATCH_DIST_THRESHOLD = 0.15` метра) — ТОЛЬКО в момент построения
шаблона (разово на уникальное имя, убедиться, что источник формы —
реально тот же физический экземпляр, что описывают `Corners` текущего
элемента). Дальнейшая расстановка копий по-прежнему НЕ трогает `.dae`.

## Статус
Подтверждено пользователем рабочим на реальном прогоне: фурнитура с
реальной геометрией из `.dae` расставляется корректно вместе с
выборочным экспортом и группировкой блоков.
